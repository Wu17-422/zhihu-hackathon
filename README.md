# 犀利评手 · 知乎评论区争议地图

> 给知乎评论区装一张「地图」：几百条评论压成几个阵营，一眼看清大家在吵什么、
> 分歧的根在哪、以及哪条好评论被排序埋掉了。

知乎评论区是最容易被忽略的信息富矿，也是最难读的地方 —— 高赞不等于对，
吵架的人经常在讨论两件不同的事，而真正有信息量的评论可能只有 2 个赞、排在 300 楼。

这个项目把一整个评论区的争论**结构化**：谁和谁在对立、各自拿什么论据、卡在哪一个判断上。

## 五个功能

| 功能 | 说明 |
|---|---|
| 🗺️ **争议地图**（首屏） | N 条评论 → 3~5 个阵营 + 各自论据 + 代表原文，渲染成一张可交互的争议图谱 |
| 🎯 **分歧根源** | 双方其实卡在哪个具体判断上，而不是「一方认为 A、一方认为 B」这种废话 |
| 💎 **被埋没的好评论** | 赞数低、排在后面，但内容质量明显高于平均的那几条 |
| ✍️ **写评论实时检测** | 边打字边概括你的观点、挑逻辑漏洞，并并行搜出相关讨论（停顿 1.5 秒自动触发） |
| 🧠 **正文转思维导图** | 把帖子/回答正文拆成结构化的 SVG 树状导图 |

**为什么首屏是争议地图而不是逐条卡片**：输入 800 条评论、输出 800 张卡片，比原文还长，
压缩工具就失去意义了。逐条分析保留，但降级成「点开才看」的细节。

## 跑起来

```bash
# 后端（Windows 下也可以直接双击 backend/start.bat）
cd backend
pip install -r requirements.txt
set ZHIHU_ACCESS_SECRET=你的key        # 或把 key 写进 backend/secret.txt
py -m uvicorn main:app --port 8000
```

浏览器打开 <http://localhost:8000/demo> 就是上面那个 Demo；
<http://localhost:8000/api/health> 确认后端活着（会打印 key 的形状，但不吐内容）。

**浏览器扩展**（可选）：`edge://extensions` 或 `chrome://extensions` → 打开「开发人员模式」
→ 「加载解压缩的扩展」→ 选中 `extension/` 文件夹。

## 几个值得说的技术点

**首屏是阵营，不是卡片。** 争议聚合把 N 条评论抽样压成 3~5 个阵营。抽样时有**一半配额
留给低赞和靠后楼层** —— 如果按赞数取 top-N，「被埋没的好评论」永远不可能出现在样本里，
因为它们的定义就是「赞数低、排在后面」。这个偏置是刻意设计的。

**大提示词必须走流式，否则必挂。** thinking 模型遇到大提示词会先「想」很久才吐第一个字，
非流式请求在这段空等里连一个字节都没有，直答服务端会把它当死连接掐掉
（`ConnectionResetError 10054`）。实测争议聚合用非流式**必挂**，换流式后稳定 25~45 秒返回。

**模型吐坏 JSON 有兜底。** 实测遇到过 `Expecting ',' delimiter`，同一个提示词重跑又是好的 ——
偶发比稳定失败更危险，因为演示时会随机降级成假数据。所以有 `_repair_json()`
修三类毛病（字符串里没转义的裸引号、尾随逗号、生成被截断），修不动就重打一次。

**接口拆开，首屏从 6 秒降到 1 秒。** 「相关讨论」只需要搜索（0.8 秒），
「逻辑漏洞」要等模型（5.3 秒）。串着跑用户 6 秒内什么都看不到，
拆成 `/api/related` 和 `/api/polish` 两个接口并行发之后，帖子 1 秒就铺出来了。

**失败一律降级，不白屏。** 任何接口出错都退回假数据并在界面上标出「🚧 假数据」和降级原因 ——
演示时白屏比数据不准糟得多。界面右上角的来源角标（🔼 直答 / 📥 缓存 / 🚧 假数据）是准的。
